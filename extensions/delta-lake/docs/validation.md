## 실제로 대조한 결과

### 초기 분류

335,000행을 Silver 271,787·격리 33,854·제외 29,359행으로 분류했습니다. 제외는 동일 반복 9,598행과 이전 유효 개정 19,761행입니다. 원본 행이 정확히 한 처리 결과에 속하는지 확인했습니다.

별도 Python 계산과 전 행의 개정·결과·필수값·충돌·순위·분류를 대조해 차이 0건을 확인했습니다. 단, Python 분류는 선행 숫자·시각·참조 후보를 입력으로 공유합니다. 그 선행 후보는 각 앞 단계에서 별도로 검증했습니다.

팀의 저장된 최종 분류와 건수는 같지만, 이 결과만으로 MySQL 최종 테이블의 모든 값도 같다고 주장하지 않습니다.

### 실제 Silver 배치 재생

이전 유효 개정 19,761행→현재 스냅샷 271,787행→반영 후 완료 기록 전 예외→재시도→완료 반복→이전 개정 지연 도착 순서로 검증했습니다.

최종 재생 결과와 초기 Spark Silver를 업무 13개 컬럼 및 출처·정제 규칙 정보 전체로 양방향 exceptAll 대조해 두 방향 차이 0행을 확인했습니다. 키 유일성, 최초 이전 개정 스냅샷 조회, 완료 반복의 대상·원장 버전 불변도 확인했습니다.

새 raw CSV를 배치별 정제한 것은 아니며 실제 프로세스 강제 종료·전원 손실 시험도 아닙니다. 예외 주입 후 새 실행 객체가 저장된 원장을 읽는 특정 중단 구간의 시험입니다.

### 일별 Gold

최종 결과 271,787행과 유효 개정 기록 291,548행을 별도로 집계했습니다. 생성한 결과 Gold 1,729행·작업량 Gold 1,729행의 모든 집계 값을 Python Decimal 계산과 비교해 일치했습니다.

건수·거래금액·정책 배상금·시간의 합계가 해당 입력 범위와 같았고 유효 기록의 시간 합계는 4,620,775분이었습니다. 결과별 건수 합, 그룹 키, 구간 경계와 누락 날짜를 임의 0건으로 만들지 않는 동작도 확인했습니다.

배상금은 CLAIM_FAKE_PASS 거래금액의 3배라는 정책 계산입니다. 실제 손실이나 개선으로 절감한 비용이 아닙니다. 과거 날짜에 묶은 결과는 현재 알고 있는 유효 개정의 재집계이며 당시 알 수 있었던 정보만을 재현한 분석은 아닙니다.

## 기존 팀 검증과 구분

기존 Pandas 482개 검사·18개 테이블·188개 컬럼, SQL 품질 통과 14·미검증 1·기준 차이 1은 [팀 저장 기록](../../../docs/validation.md)입니다. 이번 개인 확장에서 그 482개 검사를 다시 실행한 것은 아닙니다.
