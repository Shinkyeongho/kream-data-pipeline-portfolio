# 처리 결과와 검증 범위

이 문서는 **기존 팀 MySQL·Pandas 산출물에 저장된 검증 기록**입니다. 이후 개인 확장에서 직접 실행한 Spark·Delta 결과는 [개인 확장 검증 문서](../extensions/delta-lake/docs/validation.md)에 별도로 정리했습니다.



최종 산출물에 저장된 원본 행 분류는 다음과 같다.

| 분류 | 행 수 | 의미 |
| --- | ---: | --- |
| Silver | 271,787 | 검수별 최고 유효 개정 |
| Quarantine | 33,854 | 오류 행 격리 |
| Excluded | 29,359 | 동일 중복 9,598행 + 이전 유효 개정 19,761행 |
| 합계 | 335,000 | 원본 검수 수신량과 일치 |

원본의 완전 동일 중복 진단 10,000행과 최종 중복 제외 9,598행은 판정 범위가 다르다. 오류가 중첩된 행의 격리 등 처리 순서에 영향을 받으므로 같은 수치로 맞추지 않았다.

| 검증 범위 | 저장된 결과 | 해석 |
| --- | --- | --- |
| 원본 추적 검사 | 13개 검사 위반 0, SQL 진단 8개 지표 차이 0 | 저장된 원본·변환·분류 대조 기록 |
| Silver·Gold Pandas 검사 | 18개 테이블·188개 컬럼, 482개 검사 실패 0 | 해당 규칙의 검사 범위에서 실패 없음 |
| SQL 품질 점검 | 통과 14·미검증 1·상대팀 기준 차이 1 | 모든 업무 규칙의 검증 완료를 뜻하지 않음 |

상대팀 기준과 비교하면 정상은 9,013행 적고, 격리는 12,254행 많고, 제외는 3,241행 적다. 합계는 일치한다. 이 차이를 숨기거나 목표 건수에 맞춰 정상 분류를 늘리지 않고 미해결 차이로 보존했다.


## 문제별 진단과 최종 분류를 구분한 이유

ID·시간·참조 등의 문제는 같은 행에 중첩될 수 있습니다. 문제별 진단 건수를 합산해 전체 오염 행 수로 설명하지 않습니다. 표준화 대상이더라도 다른 규칙을 통과하지 못하면 Silver에 남지 않을 수 있습니다.

## 검증하지 못한 사항

- 점검 구간의 기간과 판정 조건이 없어 `MAINTENANCE_WINDOW_RULE`은 `NOT_CHECKED`입니다.
- 상대팀 기준과의 차이는 `SUPPLIER_COUNT_COMPARISON`의 `RECORDED_DIFFERENCE`로 남아 있습니다.
- 실패 0개는 실행한 검사 범위의 결과이며 데이터 전체의 무오류나 모든 업무 규칙의 검증을 보장하지 않습니다.
- 처리시간·메모리·비용의 전후 비교를 측정한 근거가 없어 성능 개선율을 제시하지 않습니다.
