# 명세 기반 검수 데이터 정제와 Bronze → Silver 적재

KREAM 스타일의 합성 검수 데이터를 대상으로 수행한 교육용 팀 프로젝트다. 프로젝트 기간은 2026.10.14~2026.10.16이다. MySQL 기반 Bronze → Silver 구현과 오염 데이터 처리·적재를 직접 담당했고, Gold 결과의 해석을 위한 데이터 검증과 추론에 참여했다. Pandas 분석 코드는 다른 팀원이 작성했으며, 그 외 작업은 공동 수행했다.

## 문제와 목표

공급받은 원천 검수 335,000행에는 식별자 표기 차이, 상품명 오타·별칭, 혼합된 금액·시간 단위, 마스터 참조 문제와 중복·개정 충돌이 섞여 있었다. 원본을 바로 집계하면 동일 검수가 중복되거나, 시간과 배상 위험이 잘못 계산될 수 있었다.

테이블·컬럼 명세서와 공식 사전을 기준으로 데이터를 진단하고, 복구할 근거가 있는 값은 표준화했다. 오류 행은 격리하고 중복·이전 유효 개정은 별도 보관해, 분석에 사용할 현재 상태와 원본 이력을 구분했다.

## 데이터와 원본 보존

| 입력 | 원본 행 수 | 역할 |
| --- | ---: | --- |
| 상품 표준 사전 | 32 | 표준명·동의어·코드·배상 배수 기준 |
| 카테고리 마스터 | 1,050 | 카테고리 참조 기준 |
| 검수원 마스터 | 3,150 | 사번·현재 소속·직급 기준 |
| 검수 원천 | 335,000 | 검수 및 개정 기록 |
| 조인 통합본 | 335,000 | 사전 결합된 마스터·배상금 값의 비교 대상 |

원천과 조인 통합본은 같은 검수 업무를 서로 다르게 표현한 파일이다. 두 파일을 합쳐 670,000개의 서로 다른 검수로 해석하지 않았다.

Bronze에서는 문자열 중심으로 원문을 보존하고 파일명과 원본 행 번호를 부여했다. 빈 문자열, 문자 그대로의 `NULL`, `NA`와 SQL NULL의 의미가 적재 과정에서 섞이지 않도록 구분했다. 메모에 포함된 지시문도 원본 텍스트로 보존하고 정제 규칙으로 사용하지 않았다.

## 명세 기준으로 발견한 문제와 처리

아래 진단 건수는 원본 문제의 발생량이다. 같은 행에 여러 문제가 중첩될 수 있어 합산해 전체 오류 행 수로 해석하지 않는다. 표준화 후보 건수 역시 최종 Silver에 적재된 수정 건수와 다르다.

| 문제 | 명세의 기준 | 원본 진단 또는 실제 사례 | 적용한 처리 |
| --- | --- | --- | --- |
| 식별자 표기 차이 | 검수 ID·사번의 전각 및 공백 정규화 | 기존 진단: 검수 ID와 사번 각각 6,000행이 정규화 대상 | 확인된 표기 차이를 정규화하고, 형식 검사와 마스터 참조 검사를 별도로 수행 |
| 상품명 오타·별칭 | 상품 코드로 사전 연결 후 표준명 복구 | 기존 진단: 원본 상품명과 코드 기준 표준명 불일치 17,100행 | 유효 코드·표준명·동의어를 근거로 복구하고, 근거 없는 값은 임의 추정하지 않음 |
| 거래금액 단위 혼재 | 원화 환산 | 직접 확인: `$` 표기 2,500행, `만` 포함 표기 2,500행. 예: `$12923.7`, `74만원` | 단위를 해석해 원화로 변환하되, 달러 금액은 프로젝트 고정 환율 **1 USD = 1,350 KRW**를 적용하고 소수 정밀도를 보존. 기존 진단의 결측 591행·음수 609행은 격리 대상 |
| 소요시간 단위·결측 혼재 | 분 단위 통일, `-999` 격리 | 직접 확인: `초` 포함 표기 2,500행, 정확히 `-999`인 값 1,200행. 예: `300초(sec)` | 초 단위를 60으로 나누어 분으로 변환. 결측 대용값 `-999`를 정상 시간이나 0으로 바꾸지 않고 격리 |
| 시각 형식·시간대 혼재 | UTC를 KST로 변환, 시간 역전 격리 | 직접 확인: 입고 시각의 `Z` 또는 `+00:00` 표기 2,500행. 기존 진단: 완료 < 입고 3,165행, 추출 < 완료 2,891행 | 시간대를 통일한 뒤 입고 ≤ 완료 ≤ 추출 관계를 검사하고 역전 행 격리 |
| 잘못된 사번·참조 | 사번으로 직원 연결, 유령 사번 격리 | 직접 확인: 사번의 빈 문자열·`NULL`·`NA` 각 400행. 기존 진단: 정상 직원 마스터에 없는 참조 5,942행 | 결측·유령·격리된 직원 참조를 구분해 판정. 동명이인이 있는 이름을 조인 키로 사용하지 않음 |
| 카테고리 참조 문제 | 상위 카테고리 FK 무결성 | 기존 진단: 정상 카테고리 마스터에 없는 참조 12,950행 | 유효 마스터와 대조하고 확인된 상품 매핑으로 복구. 이 수치는 복구 전 진단이며 전부 최종 격리 건수가 아님 |
| 중복과 개정 충돌 | 검수 ID·개정번호 복합키와 최고개정본 채택 | 기존 진단: 완전 동일 중복 10,000행, 동일 개정 내용 충돌 2,400그룹·4,800행 | 충돌한 행은 양쪽 격리. 품질 검사를 통과한 중복은 대표 행을 선택하고, 최고 유효 개정을 현재 Silver로 적재 |
| 조인 통합본의 값 불신 | 마스터 재조인, 가품 오판정 배상금은 거래가 × 3 | 직원·부서·직급과 배상금이 미리 붙은 파일이 별도로 제공됨 | 정상 검수에서 사번·카테고리로 마스터를 다시 연결하고, `CLAIM_FAKE_PASS`의 배상금만 거래가 × 3으로 재계산 |

원본 사례에 규칙을 적용하면 `74만원`은 740,000원, `300초(sec)`는 5분이다. 이는 변환 규칙의 계산 예시이며, 해당 원본 행이 다른 검사까지 모두 통과해 Silver에 남았다는 의미는 아니다.

## Bronze → Silver 구현

1. **원본 보존:** Bronze에 원문과 출처를 적재했다. 원본 적재와 값 변환을 구분했다.
2. **변환 후보 생성:** ID, 상품명, 금액, 시간, 사번·카테고리 참조의 변환 후보와 오류 플래그를 만들었다.
3. **통합 판정:** 개별 컬럼뿐 아니라 필수값, 참조, 시간 순서, 동일 개정 충돌을 함께 확인했다.
4. **행 분류:** 정상 후보·격리·제외를 구분하고 원본 행의 처리 결과를 추적했다.
5. **현재 상태 적재:** 품질 검사를 통과한 최고 유효 개정을 Silver로 적재하고 PK·UNIQUE·FK 제약조건을 설정했다.
6. **분석용 재구성:** 정상 검수와 정상 마스터를 재조인하고 배상금을 계산해 분석용 결합 테이블을 만들었다.

동일 내용 중복과 이전 유효 개정은 현재 상태에서 제외하되 이력으로 보관했다. 따라서 ‘제외’를 전부 오류 삭제라고 설명하지 않는다. Gold 작업량 분석에서는 정상 이전 개정도 실제 수행한 작업으로 포함하고, 동일 중복과 오류 기록은 제외했다.
